# Katergon CLI

Публичные готовые сборки Katergon CLI для работников и пилотных пользователей.
Исходный код, серверная часть и пользовательские данные в этом репозитории не
публикуются.

## Скачать

- [Последний выпуск: ZIP для Windows x64 и соответствующий SHA-256](https://github.com/horggorg88-pixel/katergon-cli/releases/latest)
- [Подписанный манифест установки и обновления](https://github.com/horggorg88-pixel/katergon-cli/releases/latest/download/katergon-cli-manifest.json)

Для личной инструкции проекта формата v2 требуется CLI **0.9.39 или новее**.
Проверьте фактически запускаемую версию командой `katergon version --json`.
Если версия ниже, сначала обновите CLI из подписанной поставки и проверьте её
снова. Если совместимый выпуск ещё не опубликован или обновление недоступно,
дождитесь его: установленная старая версия не подтверждает готовность к v2.

## Подключить проект через агента

1. Примите личное приглашение владельца в Telegram-боте Katergon.
2. Откройте «Мои проекты». Создайте и назовите свой проект либо выберите уже
   доступный общий проект.
3. В карточке нужного проекта получите «Инструкцию агенту» и передайте её агенту,
   открытому в рабочей папке. Для каждого аккаунта и проекта выдаётся отдельная
   личная инструкция; чужую ссылку использовать нельзя.
4. Агент проверит версию CLI. При отсутствии CLI он получит подписанный manifest,
   проверит подпись и SHA-256 указанного в нём архива, установит CLI и выполнит
   `katergon onboard` с личной ссылкой и полным путём папки.
5. Когда CLI запросит вход, лично отправьте показанную команду Telegram-боту,
   сверьте шестизначный код в терминале и боте и подтвердите свой компьютер.
   Для этого пути email и пароль не нужны; название проекта уже задано в боте.
6. Подтвердите доверие установленным hooks в `/hooks` вашего Codex. Агент покажет
   итоговую квитанцию подключения. При доступе на запись запускаются Watcher и
   первая синхронизация. При доступе только на чтение результат
   `configured/read_only` не означает готовность Watcher или индекса.

Если CLI уже установлен и обновлён, основная команда выглядит так:

```powershell
katergon onboard --bootstrap '<личная ссылка из бота>' --path 'C:\Projects\work' --output jsonl
```

Для другой папки или компьютера получите новую личную инструкцию в карточке
того же проекта. Повторно создавать проект не нужно. Не публикуйте bootstrap-ссылки
в отчётах и не пересылайте их другим работникам.

## Установка

Эти шаги может выполнить ваш агент по инструкции бота. Для ручной установки:

1. В последнем выпуске скачайте ZIP и соответствующий файл `.sha256`.
2. Проверьте контрольную сумму. Агент при автоматической установке также
   проверяет подпись manifest и использует только указанную в нём поставку.
3. Распакуйте ZIP и запустите `Install.cmd`.
4. Откройте новый терминал и выполните `katergon version --json`.

В архив уже входит проверенный Node.js 20.20.2. Устанавливать Git, npm, Node.js
или скачивать репозиторий с исходниками не требуется. Установщик добавляет только
Katergon CLI и интеграционные hooks для уже установленного Codex; сам Codex он не
устанавливает. После установки CLI проверяет подписанный манифест и применяет
проверенное обновление автоматически; недоступность сети не блокирует текущую
версию. Это не отменяет минимальную версию для нового подключения.
Локальный backend устанавливать или запускать не требуется.

## Повторный вход и старые инструкции

Если квитанция уже связанного проекта просит повторный вход, выполните
`katergon auth login --server '<адрес сервера>'`, лично подтвердите совпадающий
код в Telegram, затем выполните `katergon auth connect`. Обычный `onboard`
выполняет свой поток входа самостоятельно.

Только ранее выданные ссылки формата **v1** могут требовать точный `--email`,
скрытый ввод пароля и `--project-name` или `--yes` для неназванного резерва.
Следуйте инструкции такой ссылки. В v2 параметры `--email`, `--password-stdin`
и `--project-name` недопустимы; пароль в чат передавать не нужно.
